# הקמת שלב 0: Google Cloud, Render ודף הבדיקות

> **הערה משלב 4:** הדף `/dev/checks` הוסר, וכתובת החזרה של גוגל מופיעה עכשיו בעמוד "חיבור לגוגל" (`/settings`). המסמך נשאר כתיעוד של ההקמה המקורית. למסירה ללקוח, לאיפוס סיסמה ולהעברת Render: `docs/handoff.md`.

בסוף התהליך יהיה שירות חי ב-Render, מחובר לחשבון הגוגל שלך, עם הדף `/dev/checks` שמריץ את חמש הבדיקות של שלב 0. הכול נעשה מהדפדפן, בלי טרמינל.

יש כאן בעיה של ביצה ותרנגולת, ולכן הסדר חשוב: גוגל צריך לדעת את כתובת השירות (לאן להחזיר אותך אחרי האישור), ו-Render צריך את פרטי הלקוח שגוגל מנפיק. הפתרון: יוצרים קודם את הלקוח בגוגל בלי כתובת, מקימים את השירות ב-Render, ואז חוזרים לגוגל ומוסיפים את הכתובת שהשירות מציג.

## 1. Google Cloud

השמות של הכפתורים כאן לקוחים מהתיעוד של גוגל. אם הממשק השתנה מעט, המבנה נשאר: פרויקט ← הפעלת Drive API ← מסך הסכמה ← לקוח.

1. **פרויקט חדש.** נכנסים ל-https://console.cloud.google.com/projectcreate, נותנים שם (למשל `images2pdf`) ולוחצים Create. אחרי היצירה מוודאים שהפרויקט החדש נבחר בראש המסך, כי כל השלבים הבאים חלים על הפרויקט שנבחר.
2. **הפעלת Google Drive API.** נכנסים ל-https://console.cloud.google.com/apis/enableflow;apiid=drive.googleapis.com ולוחצים Enable.
3. **מסך ההסכמה.** נכנסים ל-https://console.developers.google.com/auth/branding. אם מופיע "Google Auth platform not configured yet", לוחצים Get Started וממלאים: שם האפליקציה ואימייל לתמיכה ← Next; ב-Audience בוחרים External ← Next; אימייל ליצירת קשר ← Next; מסמנים את ההסכמה למדיניות ← Continue ← Create.
4. **ההרשאות.** בתפריט הצד: Data Access ← Add or Remove Scopes. בתיבה Manually add scopes מדביקים את שתי השורות האלה, ולוחצים Update ואז Save:

   ```
   https://www.googleapis.com/auth/drive.readonly
   https://www.googleapis.com/auth/drive.file
   ```

5. **מעבר ל-Production.** בתפריט הצד: Audience ← Publish app, ומאשרים. הסטטוס צריך להיות In production. זה לא פרט טכני שולי: במצב Testing גוגל מבטל את ההרשאה אחרי 7 ימים, והכלי יבקש חיבור מחדש כל שבוע.
6. **הלקוח.** נכנסים ל-https://console.developers.google.com/auth/clients ← Create client ← Application type: Web application ← שם (למשל `images2pdf-web`) ← Create. את שדה Authorized redirect URIs משאירים כרגע ריק, ממלאים אותו בשלב 3.

**שימו לב לסוד:** גוגל מציג את ה-Client secret במלואו פעם אחת בלבד, ברגע היצירה. אחר כך רואים רק את ארבעת התווים האחרונים. מעתיקים מיד את ה-Client ID ואת ה-Client secret למקום בטוח (מנהל סיסמאות), כי צריך אותם בשלב הבא.

## 2. Render

השירות נוצר מהקובץ `render.yaml` שבריפו (Blueprint), כך שהסוג, האזור, התוכנית והדיסק כבר מוגדרים בו, ונשאר רק להזין את הערכים הסודיים.

1. נכנסים ל-https://dashboard.render.com ובוחרים בפינה העליונה את ה-workspace שבו השירות יישב.
2. לוחצים New ← Blueprint, ובוחרים Connect ליד הריפו `amirbiron/Images2pdf`.
3. בטופס נותנים שם ל-Blueprint, ובוחרים את ה-branch. עד שה-PR של שלב 0 ממוזג, זה ה-branch של ה-PR, כי `render.yaml` קיים רק שם.
4. Render מציג את מה שהוא עומד ליצור (שירות web בפרנקפורט, 0.5 CPU ו-512MB, עם דיסק של 1GB), ומבקש ערך לכל משתנה שמסומן להזנה ידנית. ממלאים לפי הטבלה למטה ולוחצים Deploy Blueprint.
5. ה-deploy הראשון לוקח כמה דקות. כשהוא מסתיים, כתובת השירות מופיעה בראש עמוד השירות, בצורה `https://<שם>.onrender.com`.

הערכים שמזינים:

| משתנה | מה מזינים |
|---|---|
| `WEB_PANEL_SECRET` | סיסמת הכניסה לכלי, לבחירתך. לפחות 8 תווים, ומותר בעברית. |
| `GOOGLE_CLIENT_ID` | ה-Client ID משלב 1.6. מסתיים ב-`.apps.googleusercontent.com`. |
| `GOOGLE_CLIENT_SECRET` | ה-Client secret משלב 1.6. |
| `ALLOWED_GOOGLE_EMAIL` | חשבון הגוגל שמותר לחבר. בשלב הפיתוח זה החשבון שלך. |

את `TOKEN_ENCRYPTION_KEY` לא צריך להזין: Render מייצר אותו לבד ביצירת השירות. את `RENDER_EXTERNAL_URL` גם לא, Render מגדיר אותו לכל שירות.

אם ערך הוזן לא נכון, מתקנים אותו בעמוד Environment של השירות. עדכונים עתידיים של `render.yaml` לא דורסים ערכים שהוזנו ידנית.

## 3. חזרה לגוגל: כתובת החזרה

נכנסים לכתובת של השירות ב-Render ומתחברים עם הסיסמה. בדף הבית, בכרטיס "להגדרה ב-Google Cloud", מופיעה כתובת שמסתיימת ב-`/oauth/callback`. מעתיקים אותה.

חוזרים ל-https://console.developers.google.com/auth/clients, פותחים את הלקוח מ-1.6, ובשדה Authorized redirect URIs לוחצים Add URI, מדביקים ושומרים. לפי גוגל, לוקח בין 5 דקות לכמה שעות עד שהשינוי תופס.

## 4. חיבור החשבון

בדף הבית של הכלי לוחצים "חיבור לגוגל" ובוחרים את החשבון. גוגל יציג מסך שהאפליקציה לא מאומתת. זה צפוי: זו מערכת פרטית, והאימות של גוגל מיועד לאפליקציות ציבוריות. ממשיכים דרך האפשרויות המתקדמות שבתחתית המסך.

במסך ההרשאות **מסמנים את כל התיבות**. אם תיבה אחת לא מסומנת, הכלי לא שומר את החיבור ומציג איזו הרשאה חסרה. בסוף חוזרים לכלי, ומופיע "החשבון חובר בהצלחה".

גוגל מגביל אפליקציה לא מאומתת ל-100 משתמשים לאורך כל חיי הפרויקט. לכלי עם משתמש אחד זה לא משנה, אבל זו הסיבה שלא כדאי לחבר "רק לניסיון" חשבונות אחרים.

## 5. דף הבדיקות

נכנסים ל-`/dev/checks`, מדביקים את מזהה תיקיית הדוגמה (החלק שאחרי `folders/` בכתובת של התיקייה בדרייב) ולוחצים "הרצת הבדיקות". הריצה לוקחת עד דקה.

| בדיקה | מה היא בודקת בפועל |
|---|---|
| 1 | מחפשת את תיקיית הדוגמה לפי השם שלה, ואז תת-תיקייה שלה. מציגה גם אם התיקייה שותפה איתך או בבעלותך, כי רק תיקייה משותפת מוכיחה את המקרה של הלקוח. |
| 2 | חיפוש בעברית: שם מלא, תחילת מילה, מילה שנייה, אמצע מילה, וגרש. הכלי יוצר תיקיית בדיקה בשם `צימר ג'ורג' בגליל`, כדי שבדיקת הגרש לא תהיה תלויה בשמות שבתיקיית הדוגמה. |
| 3 | יוצרת בדרייב שלך תיקייה בשם `בדיקות כלי PDF`, מעלה אליה קובץ טקסט קטן, קוראת אותו בחזרה ומוחקת את הקובץ מהריצה הקודמת. |
| 4 | מנסה לשנות שם של תמונה שהכלי לא יצר, לאותו שם בדיוק, ומצפה לחסימה. אם החשבון עצמו לא יכול לערוך את התמונה, היא מנסה גם על קובץ בבעלותך, כדי להוכיח שהחסימה באה מההרשאות של הכלי. |
| 5 | רצה בדפדפן: מציגה את אותן תמונות ממוזערות בקישור ישיר של גוגל ובנתיב שעובר דרך השרת, ומסמנת מה נטען. |

שתי הערות לפני שמסתכלים על התוצאות. בבדיקה 2, שורות שמסומנות "מידע" לא קובעות הצלחה. לפי התיעוד של גוגל, החיפוש בשם מוצא תחילת מילה ולא אמצע מילה, והשורות האלה בודקות את זה בפועל, כי זה ישפיע על מסך החיפוש בשלב 2. בבדיקה 5 התוצאה נכונה לדפדפן שבו הרצת אותה, ולכן כדאי להריץ אותה פעם אחת גם במכשיר שהלקוח עובד ממנו.

**אם בדיקה 3 או 4 נכשלת, עוצרים.** לפי ה-ROADMAP, לא עוברים להרשאה רחבה יותר לפני שבודקים מה קרה.

## 6. בדיקה אחרי 8 ימים

אחרי 8 ימים נכנסים שוב ל-`/dev/checks` ומריצים. אם מופיע מסך "צריך לחבר מחדש", ההרשאה פגה, וכנראה הפרויקט נשאר במצב Testing (שלב 1.5). הבדיקה הזו לא עוצרת את העבודה על השלבים הבאים.
